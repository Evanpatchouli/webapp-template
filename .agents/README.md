# 记忆系统使用说明

## 📁 目录结构

```
.agents/
├── README.md                 # 本文档
├── INTERACTION_GUIDE.md      # 交互策略指南
├── project-context.md        # 项目核心信息（长期维护）
└── daily-logs/               # 每日工作日志
    ├── 2026-02-01.md
    └── ...
```

---

## 🎯 文档用途

### 1. INTERACTION_GUIDE.md
**用途**: 定义高效交互策略
**何时读取**: 每次对话开始时
**内容**:
- 读取策略
- 高效交互模式
- Token 消耗警告机制

### 2. project-context.md
**用途**: 记录项目核心信息
**何时读取**: 每次对话开始时
**内容**:
- 技术栈
- 项目结构
- 核心功能模块
- 重要架构决策
- 待办事项

**更新频率**: 有重大变更时更新

### 3. daily-logs/YYYY-MM-DD.md
**用途**: 记录每日工作内容
**何时读取**: 需要回顾历史时
**内容**:
- 主要完成的功能
- 技术要点
- 注意事项

**更新频率**: 每天工作结束时（可选）

---

## 📝 日志记录规范

### 何时记录

✅ **需要记录**:
- 新增核心功能
- 重要架构决策
- 技术方案变更
- 遇到的重要问题及解决方案

❌ **无需记录**:
- 常规 bug 修复
- 代码格式调整
- 简单的文案修改
- 依赖版本更新

### 记录格式

```markdown
# YYYY-MM-DD 工作日志

## 🎯 主要完成
- 功能1: 简要描述
- 功能2: 简要描述

## 📚 技术要点
- 关键技术点1
- 关键技术点2

## ⚠️ 注意事项
- 需要注意的点
```

**原则**: 精简、关键信息、便于快速理解

---

## 🔄 维护流程

### 每日工作结束时（可选）
1. 如有重要变更，创建当日日志
2. 更新 `project-context.md` 的待办事项

### 每周回顾（推荐）
1. 整理本周重要变更
2. 更新 `project-context.md` 的核心信息

### 每月归档（推荐）
1. 合并超过 30 天的日志到 `project-context.md`
2. 删除或归档旧日志

---

## 💡 使用建议

### 对话开始时
Agent 应该读取:
1. `INTERACTION_GUIDE.md` - 了解交互策略
2. `project-context.md` - 了解项目核心信息

### 遇到问题时
使用 Grep 搜索相关日志:
```bash
grep -r "权限系统" .agents/daily-logs/
```

### 需要回顾决策时
读取特定日期的日志或 `project-context.md` 的架构决策部分

## 📊 Token 消耗预估

| 操作 | Token 消耗 |
|------|-----------|
| 读取 INTERACTION_GUIDE.md | ~800 tokens |
| 读取 project-context.md | ~1000 tokens |
| 读取单日日志 | ~200 tokens |
| 读取 30 天日志 | ~6000 tokens |

**建议**: 每次对话开始只读取前两个文档（~1800 tokens），按需读取日志
