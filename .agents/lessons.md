# 技术经验记录

## 2026-08-28

- NestJS 的全局 Guard 可以同时承载认证和基于元数据的角色/权限授权；全局 middleware 若只做 token 校验，容易与 Guard 重复执行并破坏公开接口。
- 修改后应分别运行格式检查、单元测试、核心逻辑 smoke check 和完整构建；本次完整构建暴露了与鉴权改动无关的既有 `@Todo` 类型问题。

## 2026-08-28：登出流程

- 仅使用可空的 `CurrentUser` 读取用户，不能替代路由级认证；需要由 `@Auth()` 填充用户，再用 `@AuthUser()` 保证控制器参数非空。
- 登出接口应在服务端撤销 token 后，同时让客户端清理本地会话；即使服务端 token 已过期或请求失败，也应避免界面继续保留登录状态。
