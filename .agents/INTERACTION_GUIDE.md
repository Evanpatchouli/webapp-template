# Claude 交互指南

> 本文档定义了与 Claude 高效协作的策略，帮助优化 token 使用效率

## 📖 读取策略

### 何时读取历史文档

1. **每次对话开始时** - 读取 `project-context.md`（核心项目信息）
2. **遇到具体问题时** - 使用 Grep 搜索相关日期的日志
3. **需要回顾决策时** - 读取特定日期的 daily-log

### 不需要读取的情况

- ❌ 简单的代码修改（如修复 typo）
- ❌ 独立的新功能开发（无需历史上下文）
- ❌ 回答通用技术问题

---

## 💡 高效交互模式

### ✅ 推荐做法

1. **明确具体的需求**
   - 好：「在 src/auth/permission.ts 中添加批量权限检查方法」
   - 差：「优化权限系统」

2. **批量提问**
   - 好：「检查 auth 模块的 3 个问题：1) 性能 2) 类型安全 3) 错误处理」
   - 差：分 3 次分别问

3. **提供文件路径而非粘贴代码**
   - 好：「检查 src/views/home.tsx 的布局问题」
   - 差：粘贴整个文件内容

4. **使用工具精准查找**
   - 让 Claude 用 Grep/Glob 搜索，而非读取大量文件

5. **分阶段确认**
   - 复杂任务：先确认方案 → 再执行实现

### ❌ 避免做法

1. 反复读取同一文件
2. 问过于宽泛的问题
3. 频繁切换话题导致上下文丢失
4. 生成大量代码后又不使用

---

## ⚠️ Token 消耗警告机制

当用户使用以下宽泛语句时，Claude 应**二次确认**具体范围：

### 触发二次确认的关键词

- 「优化整个项目」
- 「重构所有代码」
- 「检查全部文件」
- 「帮我看看有什么问题」（未指定范围）
- 「全面审查」

### 确认模板

```
您的需求涉及范围较广，可能消耗大量 token。
建议缩小范围，例如：
1. 指定具体模块（如 auth 模块）
2. 指定具体问题（如性能、安全性）
3. 分阶段进行

请明确您最关心的部分，我会优先处理。
```

## 📊 Token 使用参考

| 操作类型 | 预估消耗 | 建议 |
|---------|---------|------|

| 生成大量示例代码 | ~10k+ tokens | ⚠️ 确认后再生成 |
